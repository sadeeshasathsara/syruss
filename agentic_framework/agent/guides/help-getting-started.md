# Help: getting started with Syruss

What Syruss is and how a team gets from nothing to documents being read. Use the page and button names exactly as
written here; when the answer is not here or in another help guide, say you don't know rather than guess.

## The parts
- **Organization**: the top level. It has people (Sidebar: **People**), workspaces (**Workspaces**), one plan shared by
  all its workspaces (Settings → Billing), and its own **Overview** page.
- **Workspace**: one kind of document. It has its own template (what to capture from each document), its documents,
  its knowledge (people and things that appear on them), its members and roles, and its own agent (Syruss).
- **Template**: the fields Syruss reads from every document of that kind. It is versioned: Template → Current version,
  Version history, Rules, Quality.
- **Syruss AI**: the agent. It reads documents, asks people when it isn't sure, and chats in the Syruss AI panel
  (open it with the Syruss AI button; each person's chats are private to them).

## From sign-up to the first document
1. **Create an account** on the Syruss site: confirm the email address with the 6-digit code sent to it, fill in the
   profile, then name the organization. (Or sign in with Google.)
2. **Create a workspace**: Workspaces → **New workspace** (or the **New workspace** link in the sidebar). Give it a
   name and, optionally, what it's for, then **Create and add samples**. Only people whose organization role can create
   workspaces see this (owners and admins).
3. **Design the template**: the new workspace opens on **Design the template**. Upload a few typical documents; Syruss
   studies them and proposes what to capture. Notes for the agent are optional (codes your team uses, what the
   documents are for). Review the proposal and publish it: documents can be processed only once a template is
   published. Later, Template → **Refine with samples** proposes updates from new samples.
4. **Upload documents**: Documents → **Upload documents**. Each one is read as soon as it's uploaded (unless
   Settings → Documents → Intake says otherwise).
5. **Review**: what Syruss isn't sure about goes to **Review** (see the documents help guide).
6. **Invite the team**: in the workspace, Settings → Members → Invitations; for the organization, **People** →
   Invite people (see the team and roles help guide).

## Where things are in a workspace (sidebar)
Overview · Documents · Review · Agent inbox · Knowledge · Template · Analytics · Connections · Extraction log ·
Settings. Some appear only when the person's role allows them (Connections needs the "Manage API keys and webhooks"
permission; Agent inbox needs "Chat with the agent").

## Workspace settings (Settings in the workspace sidebar)
- General → Profile (name, description, formats), Plan and billing (what this workspace used), Danger zone.
- Members → People, Invitations, Roles and permissions.
- Agent → Autonomy (what Syruss may do on its own), Instructions (standing instructions it reads every time),
  Budget (a monthly cap on what Syruss uses), Reflection.
- Documents → Intake (reading on upload, accepted files), Review rules (the confidence Syruss needs to save a record
  on its own).
- Notifications → Your preferences. Integrations → API keys, Webhooks. Audit log → Activity, Agent runs.

## Organization settings (Settings in the organization sidebar)
Organization (General, Support access, Close the organization) · Billing (Plan and usage, Plans and credits,
Invoices, Billing details, History) · Your profile · Account and security (Sign-in, Trusted devices, Security
activity) · Preferences (Notifications, Appearance).
